# Brand Guidelines — Chris Garlick

## Identity

**Brand name:** Chris Garlick
Use the full name. Never abbreviate to "CG" in copy (the CG monogram is visual only, for the logo mark). Never frame it as a company ("Chris Garlick Ltd", "CG Consulting"). This is a person who does work, not a brand that employs people.

**Tagline:** Audit. Build. Maintain.
Three words. Three phases. No punctuation games, no clever wordplay. It describes exactly what happens when you hire Chris. Use it in the site header, LinkedIn headline, and email signature.

**Alternative taglines (for context-specific use):**
- "Software that actually gets used." (for blog post CTAs, cold outreach)
- "One developer. Proprietary tools. Measurable outcomes." (for case study footers, LinkedIn bio)

**One-liner:** "I build software that replaces manual work. Some of it uses AI. All of it ships."

**Brand personality (5 adjectives):**
1. Decisive — makes calls, states positions, does not hedge
2. Austere — stripped back, no excess, every element earns its place
3. Technically fluent — speaks with the confidence of someone who built the stack
4. Accountable — one person, fully responsible, no hand-waving
5. Impatient with theatre — zero tolerance for consultant-speak, hype cycles, or performative complexity

**Brand archetype:** The Craftsman-Operator
Not "The Sage" (too passive, too advisory). Not "The Hero" (too grandiose). Chris is the person who built the workshop, built the tools in the workshop, and then uses those tools to build things for other people. The proof is the workshop itself.

## Voice & Tone

### How Chris writes

- First person. Always "I", never "we" (there is no "we").
- Short sentences. Declarative. Subject-verb-object.
- Specifics over generalisations. "15 hours a week" not "significant time savings". "3 weeks" not "rapid delivery".
- States what something IS, then what it DOES, then what the result is. In that order.
- Uses periods where others use exclamation marks.
- Comfortable with silence — not every section needs a transition sentence.
- Technical terms used plainly, never to impress. If a term needs explaining, explain it in the same sentence, not in a footnote.
- Oxford comma. British English spelling (colour, optimise, analyse).

### How Chris does NOT write

- Never uses "synergy", "leverage" (as a verb), "unlock", "empower", "transform", "journey", "space" (meaning industry), "ecosystem", "disruption", "game-changer", "next-level", or "cutting-edge".
- Never uses the phrase "I help [type of person] [achieve vague outcome]" — this is LinkedIn-consultant formula copy.
- Never uses hype qualifiers: "revolutionary", "groundbreaking", "industry-leading", "world-class".
- Never uses rhetorical questions as headlines: "Ready to transform your business?" is banned.
- Never hedges with "might", "could potentially", "may help to". Either it does or it doesn't.
- Never uses passive voice to avoid accountability: "Results were delivered" becomes "I delivered the result."
- Never uses emojis in any professional copy.
- Never addresses the reader as "clients", "customers", or "stakeholders". They are "you."

### AI positioning rules

- Never call yourself an "AI expert", "AI specialist", or "AI consultant".
- Say "I'm a software developer" or "I build software".
- AI is mentioned as a tool: "I use AI where it makes sense" not "I deliver AI solutions".
- The proof is in the engineering: building your own CMS, building audit tools, shipping working software.
- Avoid making AI the hero of any sentence — make the outcome the hero.
- Say "I built software that cut their intake process from 5 days to same-day" not "I implemented an AI system that..."
- AI is one technology among many (databases, APIs, queues, AI models). List it alongside its peers, never above them.
- Never position AI as the product. The product is operational problems solved through software.

### Tone modulation

| Context | Register | Example |
|---------|----------|---------|
| **Homepage hero** | Confident, spare, declarative | "I build software that replaces manual work. Some of it uses AI. All of it ships." |

## Visual Identity Direction

### Colour

Dark editorial palette. Near-black backgrounds, warm off-white text, gold as the sole accent colour.

| Token | Hex | Usage |
|-------|-----|-------|
| `--bg-primary` | #0A0A0A | Page background |
| `--bg-secondary` | #111111 | Card surfaces |
| `--bg-tertiary` | #1A1A1A | Borders, dividers, subtle backgrounds |
| `--text-primary` | #F0EDE8 | Headlines, body text |
| `--text-secondary` | #8A8580 | Supporting text, dates, metadata |
| `--text-tertiary` | #4A4845 | Labels, captions, ghost text |
| `--accent` | #E8D5A3 | Links, CTAs, result numbers, monogram |
| `--accent-hover` | #F0E4BA | Hover states |
| `--destructive` | #C0392B | Error states only |

**Rules:**
- No blues. No purples. No greens. Warm neutrals only.
- No gradients anywhere. Flat colour, always.
- Gold accent used sparingly — CTAs, key metrics, the CG monogram. If everything is gold, nothing is.
- Background stays near-black. Never light mode at V1.

### Typography

| Role | Font | Weight | Usage |
|------|------|--------|-------|
| Display / Headlines | Instrument Serif | Regular (400) | Page titles, section headings, hero text |
| Body / UI | DM Mono | Regular (400) | Body copy, navigation, labels, metadata, form fields |
| Body / UI emphasis | DM Mono | Medium (500) | Bold text within body, button labels |

The serif/mono combination is the signature. Instrument Serif brings editorial authority. DM Mono brings technical precision.

**Rules:**
- No sans-serif. The serif+mono pairing IS the brand.
- Headlines never in mono. Body never in serif.
- No font size below 14px.
- Generous line height on body text (1.7-1.8). Let the mono breathe.

### Imagery

**What to use:**
- Architecture diagrams (hand-drawn style or clean technical)
- Screenshots of real systems (Kritano audit output, CMS admin, terminal output)
- Code snippets where they prove a point
- Simple data visualisations showing before/after metrics
- The CG monogram as the visual anchor

**What to never use:**
- Stock photography of any kind
- AI-aesthetic imagery: no gradient orbs, no neural network visualisations, no glowing blue brains
- Purple anything
- Abstract geometric backgrounds
- Illustrations in a "friendly tech" style (no blob people)

### What to avoid visually

- Rounded corners larger than 4px — keep edges sharp
- Drop shadows heavier than 0 2px 8px — light touch only
- Animations that delay content visibility
- Any visual element that says "startup" or "SaaS landing page"

## Naming Conventions

### Tools
- **Kritano** — the site intelligence / audit platform. Always capitalised, never "the Kritano" or "Kritano tool". Just "Kritano".
- **Kritano CMS** — the content management system. Always "Kritano CMS", never just "CMS" on its own in public-facing copy.
- **Kritano audit** — lowercase "audit". It's a thing Kritano does, not a product name.
- Never mention "Scalar" publicly. The /team skill and its internal name are private.

### People
- Address prospects and readers as **"you"**. Never "our clients", "our customers", "businesses we work with".
- When referring to Chris in third person: "Chris Garlick, Software Developer".
- The title is **"Software Developer"** — never "AI expert", "AI specialist", "AI consultant", "freelancer", "founder", or "agency".

### Offers
- **The Build** — the fixed-fee project.
- **The Retainer** — the monthly ongoing engagement.
- **The Audit** — the initial Kritano-powered assessment. Free when used as outreach. Part of The Build when scoped.

### Features and processes
- Keep names plain. "Document automation", not "DocuFlow AI". "Client intake system", not "IntelliOnboard".
- No branded feature names. The brand is Chris. The tools are Kritano and Kritano CMS. Everything else is described, not named.
